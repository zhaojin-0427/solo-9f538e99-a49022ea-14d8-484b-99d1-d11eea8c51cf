# 病理图像训练/验证清单划分系统 + 模型评估

Flask + SQLite 单容器应用：上传全量图像 CSV 与重复图像关系 CSV，按各类别验证张数配额，
把图像划分为**训练侧**与**验证侧**两份可下载清单；再上传验证清单的逐图预测概率 CSV，
得到各类 F1、宏平均 F1 及**按患者整组重采样**的 95% 置信区间。

## 核心业务规则

1. **连通分量是最小分配单元**：同一患者的所有图像、以及重复图像关系 CSV 中连通的图像
   （并查集合并，含传递链）必须整体在同一侧。
2. **精确满足配额**：验证侧每个类别的图像张数必须与填写的配额**精确相等**；
   多维 0/1 背包 DP 在 ≤40 张、≤4 类的状态空间内求精确解。
3. **侧别永久固定**：成功发布即把每张图像的侧别写入全局唯一的 `side_registry` 登记表。
   之后即使删除数据重新上传同一图像，其侧别也不会改变；新划分必须服从登记。
4. **无解不发布**：
   - *关联冲突 (conflict)*：一个连通分量内的已发布图像被固定在不同侧；
   - *配额不可达 (quota)*：锁定图像已超配额，或自由分量不存在精确凑出配额的组合。
   页面给出人类可读原因 + 结构化诊断（最接近的可达组合、自由分量向量等），不产生清单。
5. **更正即新版本**：重新上传 CSV 或修改配额都会生成新输入版本，旧版本立即变为
   `superseded`，旧清单仅作历史保留、**下载停供**；新版本重新划分成功后下载才恢复。
6. **求解期间可更正，过期依据不发布**：作业发布前复查版本新鲜度，版本已过期则判 `stale`
   失败，不写任何分配。
7. **并发与原子性**：
   - 部分唯一索引保证同一版本至多一个进行中/成功作业、至多一份已发布清单；
   - 清单、明细、侧别登记在单个 `BEGIN IMMEDIATE` 事务内提交，失败整体回滚，
     不会留下半次分配；
   - 服务重启时残留的 `queued/running` 作业一律标记 `restart` 失败（它们从未写入分配）。
8. **规模限制**：最多 40 张图像、4 个类别。

## 模型评估规则

1. **上传格式**：首行表头，必须含图像号列（`图像号` / `image_no` 等）和**当前输入版本
   的全部类别列**（列名与类别名完全一致）；不允许多余列。每行是图像号 + 各类别概率。
2. **整份拒绝**：数据行必须与当前验证清单**恰好一一覆盖**。以下任一情况整份拒绝、
   不写任何评估记录：图像号重复；出现训练侧/清单外图像；缺少验证图像；概率不是
   数字或非有限值（NaN/Inf）；概率超出 [0,1]；同一行概率和与 1 的偏差 > 1e-6；
   输入版本无类别；**当前验证清单为空**。
3. **真值与指标**：以验证清单的类别为真值，预测取概率最大的类别（并列取类别集合
   靠前者）。展示各类 TP/FP/FN、F1、宏平均 F1。始终使用**完整类别集合**求宏平均，
   某类分母为 0 时该类 F1 记 0。
4. **患者整组 bootstrap**：重采样单元是患者（同患者多图整组进出），有放回抽取
   `n_patients` 个患者、重复 **1000** 次，取宏平均 F1 的 2.5%/97.5% 分位数作为 95%
   区间。随机种子固定并随记录入库，同一数据可复现同一区间。每次重采样都沿用完整
   类别集合、分母为 0 的类别记 0。
5. **版本绑定与当前标记**：评估记录绑定发起时的 `version_id` 与 `manifest_id`。
   “复查当前版本/清单 + 清旧当前标记 + 写入新记录 + 逐图预测明细”在单个
   `BEGIN IMMEDIATE` 事务内完成；若解析期间输入被更正，事务内复查判过期（stale），
   整份拒绝且不写库，**不会留下标为当前、却依据旧版本的结果**。
6. **历史查看**：更正产生新版本时，旧版本的评估同步清掉当前标记，旧结果仅作历史
   查看；新版本重新划分并上传预测后才有新的“当前”评估。

## 目录结构

```
app/
  db.py          SQLite 建表、索引、连接与重启恢复
  parser.py      CSV 解析（划分输入 / 预测概率）、输入校验、并查集
  solver.py      锁定校验 + 多维 DP 精确配额 + 无解诊断
  evaluation.py  F1 / 宏平均 / 患者整组 bootstrap（固定种子）
  service.py     输入版本、作业调度、原子发布、评估落库、历史与下载
  web.py         Flask 路由
  templates/     中文网页（当前版本/作业原因/历史/评估/永久登记）
wsgi.py          waitress 生产入口
tests/           59 项 pytest（求解器、网页流程、评估解析/指标/事务）
samples/         示例 CSV（images.csv/dups.csv 划分输入，predictions.csv 预测概率）
Dockerfile, docker-compose.yml
```

## 启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8080
```

SQLite 数据保存在命名卷 `pathology_data`（容器内 `/data/pathology.db`），重启不丢。
健康检查由 Compose / Dockerfile 内置。

## 本地运行（无 Docker 时）

```bash
pip install -r requirements.txt
DB_PATH=./data/pathology.db python wsgi.py
# 自测：
PYX_SYNCHRONOUS=1 python -m pytest tests/ -q
```

## CSV 格式

全量图像 CSV（首行表头可省略，列顺序固定）：

```
图像号,患者号,类别
IMG001,P001,肿瘤
IMG002,P001,肿瘤
```

重复图像关系 CSV（可不上传）：

```
图像号A,图像号B
IMG003,IMG006
```

逐图预测概率 CSV（列须与当前输入版本类别完全一致，这里假设类别为 肿瘤/正常/炎症/异型增生）：

```
图像号,肿瘤,正常,炎症,异型增生
IMG001,0.82,0.10,0.05,0.03
IMG004,0.04,0.88,0.06,0.02
```

行必须与当前验证清单图像恰好一一对应；概率为有限实数、和与 1 的偏差 ≤ 1e-6。

示例数据可直接走通全流程：上传 `samples/images.csv` + `samples/dups.csv`，
配额填 `肿瘤=2、正常=1、炎症=0、异型增生=1`，发起划分后上传
`samples/predictions.csv`（其图像恰好是该配置下的验证侧）。

## 页面操作

- **当前版本 `/`**：上传/更正 CSV、填写各类验证张数、发起划分、查看当前清单与下载两侧 CSV；
  页面底部⑤上传预测概率 CSV 并查看当前评估摘要；
- **作业页 `/jobs/<id>`**：求解状态自动轮询；失败时展示关联冲突/配额不可达原因与诊断；
- **模型评估 `/evaluations`**：全部评估记录（当前/历史）；`/evaluations/<id>` 展示逐类
  TP/FP/FN、F1、宏平均 F1、患者整组 bootstrap 95% 区间、逐图预测、患者级计数与原始 CSV 留档；
- **历史 `/history`**：所有输入版本、作业（含失败原因）、已发布清单、评估记录；
  历史版本下载停供，旧评估仅作历史查看；
- **永久侧别登记 `/registry`**：全局图像侧别锁定表。

下载文件为 UTF-8 CSV：`图像号,患者号,类别,侧别,连通分量`。
